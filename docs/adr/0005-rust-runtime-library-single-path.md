# ADR 0005 — 运行态 Rust 动态库的唯一路径与单一解析入口

- **日期**：2026-04-08
- **状态**：已采纳
- **决策者**：@alexc

---

> 来源：原 plans 文档《2026-04-08 Rust 动态库运行态路径统一设计》
> （plans 目录已整体删除，本文是该设计的决策提取）。

## 背景

当时 Flutter 运行链路、FRB 真库测试链路与 macOS app bundle 拷贝链路对动态库位置的依赖并不统一：
有的链路直接读 Cargo 产物目录，有的在 app build 后再复制到 bundle，有的依赖 FRB 默认相对目录解析。
历史问题反复表现为「新 worktree/新环境找不到动态库」「Dart 绑定与 Rust 库版本不同步」
「运行与测试用的不是同一份产物」。

根因归纳为三条：构建缓存目录被同时当成运行态真相源；动态库路径解析缺少单一入口，
测试/运行/打包各自拼路径；没有约束「哪些代码可以直接读取 Cargo 产物目录」。

## 决策

1. **区分「Cargo 编译缓存」与「运行态产物」**：Cargo 产物目录只由构建脚本读取，
   任何运行态代码、测试与 helper 不得把它当作运行输入。
2. **运行态动态库只保留唯一官方路径**，由构建脚本在 `cargo build --release` 之后从 Cargo 目录同步。
   路径按平台分目录（当时落地 macOS，命名为 `build/native/<platform>/` 规则）。
3. **同步失败语义固定**：
   - `cargo build --release` 失败 → 该命令直接失败，禁止继续同步旧产物；
   - 构建成功但源库不存在、复制失败或目标目录写入失败 → 命令同样必须失败；
   - 进入写入阶段前先删除旧的官方运行态库，禁止同步失败后保留旧副本继续被当作运行输入。
   即官方运行态目录只允许两种状态：**本次成功同步后的新库**，或**不存在**（后续测试/运行必须显式失败）。
4. **Dart 侧只保留一个路径解析入口**：返回当前平台运行态动态库的绝对路径；
   只负责定位与校验，**不触发构建、不兜底回退到 Cargo 目录**；缺失时必须给出可指导恢复的错误。
5. **真实初始化必须显式加载官方运行态路径**：先 `ExternalLibrary.open(<运行态路径>)` 再 `RustLib.init(...)`；
   不得把 FRB 默认相对路径解析当作隐式后备路径（生成代码里的默认 loader 配置可以保留，但真实链路不得依赖它）。
6. **测试链路收口**：FRB 合同测试、真库集成测试与任何提供 dylib 路径的 helper/fixture 统一走该单点入口；
   纯 mock 测试与不加载真库的普通单测不在收口范围。
7. **run/打包链路也从运行态路径取库**：app bundle 拷贝不再直接从 Cargo 目录复制，
   以保证 bundle 与测试使用同一份运行态产物。

## 拒绝的方案

### 方案 B：保留 Cargo 路径，只统一 Dart 侧加载入口

- 优点：改动更小，能减少散落硬编码。
- **拒绝理由**：根因未消除——运行态仍依赖 Cargo 目录，worktree、执行目录与构建缓存生命周期问题仍然存在；
  app bundle 与测试链路仍可能各自复制、持有不同副本。

### 方案 C：本轮就统一全局共享 `CARGO_TARGET_DIR` 并统一运行态目录

- 优点：构建复用最好，worktree 切换成本最低。
- **拒绝理由**（本轮）：需要引入更强的环境与团队约束，超出「先稳定运行态来源」的最小范围。

### 被否决的兜底行为

- **运行态缺库时静默回退到 Cargo 目录**：拒绝，会让「Cargo 已变但运行态仍是旧副本」的版本漂移重新出现。
- **检测到缺库自动后台重建**：拒绝，本轮不做隐式构建。

## 后果

- **正向**：运行态只有一个真相源；测试与运行加载同一份产物；后续若要切换共享缓存策略，只需调整构建源，
  不必重写运行侧代码。
- **成本/负向**：需要收口既有路径硬编码；构建脚本增加「产物同步」职责与失败语义。
- **约束**：运行态代码与测试中不得再手写 Cargo 产物路径；路径解析逻辑不得在多个测试文件里重复定义。

### 现状核对（2026-10）

- **决策已落地并扩展到多平台**：
  - macOS 运行态为 `build/native/macos/` 下的 dylib，由 `tool/build.dart`（`lib` 子命令）同步；Android 由同一脚本经 cargo ndk 产出 .so 并校验到打包库目录。
  - Windows / Linux host 运行态由门禁模块 `tool/src/git_gate/host_build.dart` 同步（Windows 目标为 Flutter 打包产物内的 DLL 路径，Linux 为 bundle 的 lib 目录），并保留了「先删旧、再复制」的语义。
  - Dart 侧单一解析入口是 `lib/bridge/rust_library_loader.dart`（`resolveBundledRustLibraryPath`），
    按 macos/ios、windows、linux 分派候选路径；应用启动（`lib/main.dart`）与真库集成测试
    （`integration_test/support/test_harness.dart`）都经它加载。
- **与当时设计的差异（已演进，不是回归）**：
  - 当时「本轮只落地 macOS，非 macOS 调用必须抛未支持错误」的阶段约束已被跨平台实现取代。
  - 当时「必须显式失败」调整为：**打包链路**缺库即失败；**开发/测试态**入口返回 null 后由调用方回落
    FRB 默认解析（即 Cargo 产物目录），以保证开发态与单测不回归。
    这是对第 5 条「不得依赖默认解析」的务实放宽，FRB 生成代码中的默认路径仍指向 Cargo 产物目录。
  - 当时要求的「错误消息必须包含标准恢复命令」在当前代码中没有对应实现：
    `lib/bridge/rust_library_loader.dart` 缺库时返回 null，由 FRB 默认加载逻辑报错，不再附带构建指令。
  - 库名随 crate 变化：当时的 `libcardmind_rust` 现为 `cardmind_backend`（`rust-backend/Cargo.toml` 的 crate 名）。
