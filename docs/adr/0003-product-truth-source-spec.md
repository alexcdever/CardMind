# ADR 0003 — 建立产品级上位真相源

- **日期**：2026-03-19
- **状态**：已采纳
- **决策者**：@alexc

---

> 来源：原 plans 文档《CardMind 产品深度审计》《CardMind 产品审计设计》与《Product Truth Source Implementation Plan》
> （plans 目录已整体删除，本文是该批文档收束出的长期决策）。

## 背景

2026-03-19 的产品深度审计结论是：CardMind 的**工程治理成熟度已经明显超过产品成熟度**。
工程侧已有正式规格、计划、质量门禁与上下文恢复机制；产品侧却缺少与架构、池、卡片规格对应的上位产品原则文档，
产品价值、用户心智与长期体验原则散落在 README、设计文档、用户指南和历史计划里。

审计据此把「建立统一的产品层规格或产品原则文档」列为高杠杆改进点第一条，
并判定根问题是「产品层真相源不够集中，AI 难以稳定继承产品判断」——
AI 擅长把局部实现做对，却缺少一层显式的产品判断基线。

## 决策

1. **新增产品级上位真相源文档**（当时落在正式规格目录，题为「产品定位与阶段目标规格」），
   显式定义：终极目标、当前阶段目标、目标用户、核心价值承诺、核心能力与能力边界、非目标、与下游规格的关系。
2. **终极目标表述**：成为一款面向多设备个人用户、用于同步和流转笔记数据的应用。
3. **当前阶段优先证明三件事**：
   1. 个人用户可在本地优先前提下稳定创建、编辑、查询笔记；
   2. 同一用户跨设备同步笔记数据的体验可解释、可恢复、可长期信任；
   3. 数据池协作是同步与流转模型的扩展能力，**不得压过个人多设备主路径的优先级**。
4. **目标用户为拥有多设备场景的个人用户；非目标为复杂团队协作、多角色组织流程、扩张型平台化能力**
   （当前阶段不以它们为第一优先级）。
5. **真相源演进顺序**：产品目标若发生变化，必须**先更新产品级真相源，再更新下游规格或实现**，
   不允许下游文档或实现自行漂移。
6. **公开入口文档必须对齐真相源**：README 与用户指南只承诺当前规格支持的行为，
   用户指南须显式声明「只描述当前支持的公开行为」，正式产品/行为约束以正式规格为准。
7. **私有作者背景不进入版本控制**，保留在本地私有上下文文件中。

## 拒绝的方案

### 维持现状：产品定位继续分散在 README 与设计文档里

**拒绝理由**：审计把「产品级真相源不集中」列为根问题之一；分散表述会让 AI 与后续实现持续读到时间层不一致的文档，
增加误判与返工，也让产品优先级判断缺少可引用基线。

### 把私人背景写进受版本控制的文档来补足产品判断

**拒绝理由**：会把个人语境固化为公开承诺；改为本地私有上下文，仓库只承载可公开继承的产品目标。

### 保留用户指南中「更全但不准确」的超前描述

**拒绝理由**：审计点名「导出 JSON」「回收站」「冲突时手动选择」「重新连接」「扫码加入」等描述与当时的正式规格/主路径不一致，
构成高风险文档漂移；对齐方式是删除或弱化，而不是保留承诺。

## 后果

- **正向**：产品判断有单一上游；下游规格、交互、文案、roadmap 有可引用基线；AI 排序候选任务时有显式依据。
- **负向**：文档面增加一层，公开入口文档（README、用户指南）需要随真相源同步维护。
- **风险**：若真相源与既有正式规格冲突，正确做法是停下更新计划或请人确认，而不是靠直觉静默调和。

### 现状核对（2026-10）

- 「产品级上位真相源」这一决策**仍然生效**，但载体与内容已演进：
  原规格目录在后续文档治理中被整体删除（提交 d7db7082），产品文档保留并移至 `docs/product.md`；
  其「当前阶段」已从「笔记编辑器 + 列表」升级为分布式个人知识库，核心能力优先级为双向链接 P0 / 全文搜索 P1 / 标签管理 P2。
- **目标用户表述已被后续决策收窄**：2026-06-16 起，目标用户从「多设备个人用户」收窄为「跨平台个人用户
  （Android + Windows + macOS 混用）」，理由与替代方案见 `docs/product-decisions.md`。
  因此本文第 2、4 条中的用户表述是**当时结论**，不是当前真相源原文。
- 用户指南文档本身也已在同一次治理中被删除；其「只承诺当前支持行为」的约束精神现在由 `docs/product.md` 与
  `CONTEXT.md` 承担。
